Bitcoin shows the money.

The ledger records what moved and never who moved it. But moments before a transaction reaches the ledger it crosses the peer-to-peer network — and there, it carries an address. STRATA reads both layers and joins them.

The method

Two layers. Neither is evidence alone.

Every existing tool reads one of these. Reading both is the entire contribution.

Layer 1 · The ledger

Permanent, public, worldwide. Records the transaction, the wallets, the amounts, the fee, the script type. Contains no identity and no address of any host.

Layer 2 · The network

Temporary, local, gone in seconds. Records which host announced the transaction, to whom, and at what instant — accurate below one millisecond. Contains no money.

The join

One observation proves nothing — any transaction can arrive first from any peer by chance. But when an entity's transactions are first-relayed from the same host far more often than that host leads traffic generally, chance stops being a plausible explanation.

Repetition is the evidence,
never a single packet.

STRATA produces a probability, not a verdict. Every lead carries the count it rests on and the likelihood of seeing that count by accident — corrected for the number of host-and-entity pairs tested, so no lead is one lucky coincidence pulled out of many.

An analyst opening a case sees the candidate host, the sightings behind it, and the named factors that produced the score. Never a number on its own.

What it does

Evidence an analyst can act on.

Four things the system produces, each of them measured rather than described.

Dual-layer fusion

The ledger and the network share no key except approximate time. Joining them on that is the whole contribution — and it is what turns a wallet address into a host.

Origins, resolved

Every attributed host is resolved to a country and network operator from a GeoIP database that ships inside the repository. No lookup leaves the machine.

Explainable alerts

Never a bare score. Every alert carries the factors that produced it, measured with SHAP, so an analyst can interrogate the reasoning instead of trusting it.

Rigour

The control that caught our own mistake.

The most useful result in the project is one that failed.

176 confident leads, at 98.9% precision. It looked excellent.

So we shuffled the entity labels — destroying every real association while leaving the structure intact. A sound method should then find nothing. Ours still produced 41 significant leads.

The cause was multiple comparisons: hundreds of host-and-entity pairs tested at a threshold of 0.01, where one in a hundred passes by construction. The false positives were built into the test. Correcting for it took the null to zero and improved precision.

Before · shuffled control
41 leads
After · shuffled control
0 leads

Without that control this would have shipped looking correct. It is the reason every stage now carries a negative control alongside its tests.

Runs with the network switched off.

No external service, no cloud database, no outbound request. The GeoIP database ships inside the repository — because when an intelligence agency asks a question, the question itself is the secret, and a query sent to a foreign vendor leaks the investigation to the act of investigating.
